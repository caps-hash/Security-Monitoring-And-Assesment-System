# Security Personnel Assessment System

Phase 1 foundation for Global Ground Force Security Agency Inc. The application
uses Next.js, TypeScript, Tailwind CSS, Supabase Authentication, and PostgreSQL.

## Requirements

- Node.js 20.9 or newer
- A Supabase project

## Local setup

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env.local`.
3. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` to the
   project's Supabase URL and public anon/publishable key. Set
   `SUPABASE_SERVICE_ROLE_KEY` to the project's service-role key in the server
   environment so HR can create staff accounts. Never expose this key in a
   `NEXT_PUBLIC_` variable. Account email is sent only when `RESEND_API_KEY`
   and `EMAIL_FROM` are set. SMS is sent only when Twilio
   (`TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`) or Semaphore
   (`SEMAPHORE_API_KEY`) is set. Leave them unset to skip that notice.
4. In the Supabase SQL Editor, run [`supabase/schema.sql`](./supabase/schema.sql).
   The script is safe to re-run and creates the profile, personnel, assignment,
   duty configuration, and row-level security policies used by the app. Re-run
   it before using Duty Assignment Management.
5. Create the initial HR account in Supabase Authentication. New auth accounts
   default to the `employee` role. Promote the first HR account from the trusted
   SQL Editor, for example:

   ```sql
   update public.profiles
   set role = 'hr'
   where email = 'hr@example.com';
   ```

   HR can then create employee and supervisor accounts from Personnel. If
   Personnel reports that `profiles.middle_name` does not exist, run
   [`supabase/migrations/20261023_add_profile_name_and_notice_columns.sql`](./supabase/migrations/20261023_add_profile_name_and_notice_columns.sql)
   in the SQL Editor. It only adds optional columns and does not delete rows. Temporary passwords are delivered only by the
   configured SMS provider and must be changed at first sign-in.
   Role values are `hr`, `supervisor`, and `employee`; role changes are not
   exposed in the application.
6. Start the app with `npm run dev` and open
   [http://localhost:3000](http://localhost:3000).

The Supabase service-role key is used only by server-side account creation
and attendance evidence writes. It must never be placed in a `NEXT_PUBLIC_`
variable or exposed to the browser.

## Phase 1 and 2 behavior

- Sign-in uses Supabase email/password authentication.
- Sign-out clears the Supabase session.
- Dashboard routes verify the authenticated user and read their role from
  `public.profiles` on the server. A user entering another role's dashboard is
  redirected to their own.
- Supabase session cookies are refreshed for dashboard requests.
- HR can create employee and supervisor accounts, edit staff profiles,
  activate/deactivate accounts, manage duty configurations, and assign employees
  to a supervisor and post with location, shift, and start date. Both roles are
  created from the Personnel tab; no separate account page is used. Employee IDs
  are generated by the server and are not edited later. HR can edit either role's email from that list. The
  change is applied to Supabase Auth and `profiles.email` without recreating
  the account. Duty assignment
  management saves a post, location, and shift together. It does not collect GPS
  or geofence fields and does not create an employee assignment. Those tools are
  on the HR sidebar: Personnel, Supervisors, and Duty assignment.
- Supervisors can see only employees assigned to them. Employees can see only
  their own profile and assignment.
- Account deactivation blocks application access; HR can reactivate an account.
- DTR, assessment scoring, SMS, and reports are not part of Phase 2.

## Phase 3 behavior

- Employees have a responsive dashboard sidebar, a dashboard overview, dedicated profile and assignment pages, and a separate account-settings page.
- The dashboard, profile, and assignment pages show the assigned post, duty location, duty shift, and start date from the employee's own current assignment.
- The employee dashboard shows assignment details. Assessment scheduling is implemented in Phase 5. Attendance recording is implemented in Phase 4.
- Employees can change their own Supabase password after entering the current password. The minimum length is 6 characters, matching Supabase's default password policy.
- Employees cannot edit HR-controlled fields such as name, role, status, phone, employee number, or assignment. No new profile-update policy was added.

## Phase 4 behavior

- Employees record Time In and Time Out from My DTR. Each action requires GPS and a live camera photo. The photo is watermarked in the browser and stored in the private `attendance-evidence` bucket. The official timestamp is set in the database and does not trust the device clock.
- There is no facial recognition or biometric matching.
- GPS is mandatory. A geofence is enforced only when HR saves latitude, longitude, and a radius together on the duty location. No default radius is invented. If those fields are blank, GPS is stored and the verification is `gps_captured_no_geofence`.
- Reverse geocoding runs only when `ATTENDANCE_GEOCODING_URL` is set to an approved HTTPS endpoint. Otherwise the place label is not resolved.
- One open session and one record per employee per Philippine date are enforced. Overnight Time Out stays on the Time In record. Missing Time Out is left blank.
- HR and supervisors can review records in scope. Employees cannot insert, update, or delete attendance through the client. There is no attendance correction, approval, leave, overtime, or payroll workflow.
- Daily, weekly, and monthly summaries list scheduled work, late arrivals, missing Time In, and missing Time Out. A day is scheduled only after HR saves weekdays on that shift in Duty assignment. There is no grace period and no official absence ruling.
- No evidence retention period is defined, so photos are kept until an approved policy exists.
- Re-run [`supabase/schema.sql`](./supabase/schema.sql) in the Supabase SQL Editor before using attendance summaries or assessment tracking.

## Phase 5 behavior

- HR saves evaluation intervals and a due-soon window. No interval is assumed.
- Synchronizing schedules creates Evaluation 1, 2, and 3 from the assignment start date. Repeating it does not duplicate rows or overwrite submitted, reviewed, returned, or completed evaluations.
- Date-based statuses are Upcoming, Due Soon, Due, and Overdue. Workflow statuses are Submitted, Under Review, Returned for Correction, and Completed. Supervisors can record submission for assigned personnel only. HR records review, return, and tracking completion. This does not upload forms, enter scores, or issue Passed / Not Passed.
- Employees see only their own schedule. Results stay unreleased.
